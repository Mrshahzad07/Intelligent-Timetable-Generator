Executive Summary

ChronosAI is an autonomous, constraint-aware academic scheduling platform that solves high-dimensional timetable generation across multiple divisions, faculty members, subjects, classrooms, and time slots while detecting and diagnosing mathematically impossible or conflicting constraints.

Powered by a dual-engine architecture:

  • Deterministic CSP Engine — Backtracking search with MRV & Degree heuristics, forward checking for instant sub-50ms conflict-free solutions.
  • Evolutionary Genetic Algorithm (GA) — Multi-generational chromosome population evolution with tournament selection, crossover, and mutation optimizing soft constraint fitness in real time.
  • Natural Language AI Scheduling Agent — Autonomous ingestion of unstructured curriculum text with a 5-step guided interview wizard.

Approach, Assumptions, Architecture & Trade-offs

Algorithmic Approach — CSP Formulation

Academic scheduling is modeled as a Constraint Satisfaction Problem (CSP) defined by the triple ⟨X, D, C⟩:

  • Variables (X): Each required class session si,k (course s, session instance k ∈ [1, weeklySessions]). Lab sessions are modeled as atomic 2-period continuous blocks.
  • Domains (D): Discrete tuples (d, p, r) — Day d, Starting Period p, Room r.
  • Hard Constraints (Chard): 7 mandatory constraints with 0 violations allowed:
    1. Teacher Uniqueness: ∀t, d, p: ΣSessions(t, d, p) ≤ 1
    2. Room Uniqueness: ∀r, d, p: ΣSessions(r, d, p) ≤ 1
    3. Division Uniqueness: ∀div, d, p: ΣSessions(div, d, p) ≤ 1
    4. Room Capability & Capacity: Type and seating match requirements.
    5. Continuous Practical Blocks: Labs occupy [p, p+1] without crossing breaks.
    6. Teacher Availability: No assignment during unavailable slots.
    7. Institutional Break Protection: No assignment during lunch/recess.

Heuristics Implemented

  • Minimum Remaining Values (MRV) / "Fail-First" — Variables with smallest legal domain are scheduled first. Lab sessions placed before theory lectures. Faculty with high unavailability prioritized.
  • Degree Heuristic — Variables involved in most constraints with other unassigned variables are placed first.
  • Least Constraining Value (LCV) — Time slot values that preserve maximum flexibility for remaining sessions are preferred.

Genetic Algorithm (GA) Evolutionary Engine

  • Chromosome Representation: Schedule encoded as array of genes ⟨subjectId, divisionId, facultyId, roomId, dayIndex, periodIndex, duration⟩.
  • Fitness Function: Hard constraint adherence (severe penalty) + soft criteria (subject dispersion, faculty fatigue, room utilization).
  • Selection: Tournament selection for fittest candidates.
  • Crossover: Single-point crossover preserving multi-period block atomicity.
  • Mutation: Random re-assignment to legal slots without violating lunch boundaries.
  • Live Progress: Real-time evolutionary convergence via animated UI indicators.

Assumptions

  1. Atomic Lab Sessions: Practical sessions are 2 consecutive periods and cannot be split across days or interrupted by lunch.
  2. Deterministic Time Grid: Discrete hourly/standardized period slots with a fixed institutional lunch break.
  3. Single Primary Instructor: Each lecture session is led by one designated faculty member.

Trade-offs Analyzed

Approach Trade-off Consideration Decision in ChronosAI
CSP vs Pure GA GA can struggle with strict hard constraints (invalid individuals needing heavy repair). CSP with forward checking guarantees 100% hard constraint satisfaction. Dual Architecture: CSP for guaranteed hard satisfaction; GA for evolutionary soft optimization.
Client-Side vs Server-Side Server-side enables heavy LP solvers (Gurobi, OR-Tools) but requires backend infra. Client-side provides instant reactivity and zero setup. Optimized client-side JS: Bitmask-indexed CSP runs in 10–50ms in browser.
Static Demo vs Dynamic AI Hardcoded demo data prevents real-world usage. Purely blank form is intimidating. Dynamic Hybrid: Zero dummy data + NL AI parser + 5-step wizard.

Handling Impossible & Conflicting Constraints

Pre-Flight Feasibility Detection Engine

Rather than allowing the solver to stall indefinitely or fail silently, ChronosAI runs mathematical feasibility checks before solving:

Impossible Condition Mathematical Rule User Notification & Diagnostic
Division Slot Overflow ΣHours > Ndays × Nperiods Pigeonhole Alert Displays required hours vs available weekly slots with exact excess count.
Faculty Overload ΣHours > MaxWeeklyfac Contract Violation Flags teacher ceiling breach, identifies overloaded courses.
Faculty Unavailability Clash AssignedHrs > AvailableSlotsfac Impossible Availability Teacher has marked too many off-slots.
Laboratory Deficit LabSessions > Nlabs × BlocksPerDay Lab Bottleneck Proves labs cannot host total practical sessions.
Room Seating Shortage ∀r: Capacity(r) < CohortSize(div) Capacity Deficit Division count exceeds largest available classroom.

Interactive Conflict Resolver & 1-Click Auto-Fix

  1. The Mathematical Feasibility Drawer opens automatically with visual diagnostic cards.
  2. Each conflict provides an Actionable Recommendation (e.g., "Add 1 additional Computer Lab or reduce lab sessions").
  3. Automated Fix Buttons allow administrators to resolve issues with 1 click (e.g., "Trim 4 excess hours from CS-A", "Add CL-02 Computing Lab").

Validation & Important Edge Cases

Validation Strategy — Four Testing Layers

  1. Mathematical Pre-Flight Validation: Algebraic capacity, pigeonhole bounds, and bipartite matching feasibility checked before the combinatorial search space.
  2. Deterministic Constraint Invariant Testing: Exhaustive pairwise checking of all generated time slots guaranteeing zero double-bookings.
  3. Interactive Validation Layer: Real-time checking during drag-and-drop, slot reassignment, and subject modifications.
  4. AI & Evolutionary Invariant Auditing: Validating NL parsing accuracy, blank canvas edge conditions, and chromosome validity across GA generations.

AI Output That Was Wrong

  1. Extensionless Relative Module Imports: Files imported without .js extensions. Vite resolved them in browser, but Node.js ESM execution failed with ERR_MODULE_NOT_FOUND.
  2. Missing Blank Canvas / Zero-Entity Handling: Initial solver assumed arrays were always populated. Clearing data caused Cannot read properties of undefined (reading 'length').
  3. Print Layout Clipped in Browser Print Preview: Initial @media print rules didn't enforce landscape orientation or hide interactive UI elements.
  4. Day/Light Mode Incomplete Overrides: Several modals, inputs, and diagnostic messages relied on hardcoded dark-mode colors, making them low-contrast in Day Mode.
  5. Intrusive Generation Sparks & Non-Intuitive Close Button: Confetti particles fired on generation success; modal close buttons remained gray on hover.

How I Identified the Problem

  1. Running node tests/verifySolver.js produced ERR_MODULE_NOT_FOUND for extensionless imports.
  2. Testing "Clear All Data" caused unexpected division overflow errors on 0 sessions.
  3. Launching window.print() in Chrome revealed table headers splitting across pages and navbar bleeding into printable area.
  4. Auditing in Light Mode across all modals revealed insufficient contrast for textareas, inputs, active pills, and feasibility cards.
  5. User feedback pointed out particle sparks and requested red hover on modal close buttons.

How I Fixed It

  1. Added .js Extensions: Enforced explicit paths across all solver and preset import statements.
  2. Engineered Blank Canvas Guards: Updated feasibilityChecker.js and timetableSolver.js to check for zero-entity inputs upfront, returning empty state objects with guidance.
  3. Hardened Print Engine CSS: Added @page { size: A4 landscape; margin: 8mm; }, isolated printable containers, hid all non-print UI controls.
  4. Engineered Day/Light Mode Design System: Built exhaustive [data-theme="light"] overrides ensuring WCAG-compliant contrast for all headings, inputs, textareas, pills, conflict cards, and table headers.
  5. Red Cross Mark Hover & Spark Elimination: Updated .btn-close:hover with red background (#ef4444), white icon, scale transition; removed canvas-confetti triggers.
  6. Automated Regression Suite: Maintained 20-test verification suite achieving 100% pass rate.
